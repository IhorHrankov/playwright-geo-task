# Код-ревʼю автотестів

Мета — знайти тести, які **дають хибну впевненість або нестабільні**. Стиль другорядний: `scripts/lint.sh`
(ruff, pycodestyle, стиль тестів) уже перевіряє його автоматично. Еталон правил — `docs/test-guidelines.md`.

## Порядок роботи

1. **Визнач обсяг:** `git diff main...HEAD` і незакомічені зміни або вказаний PR. Читай змінені файли
   повністю, а не лише диф.
2. **Запусти автоматику:**
   ```bash
   scripts/lint.sh
   .venv/bin/pytest <змінені файли> --browser chromium
   .venv/bin/pytest <змінені known_bug-тести> --runxfail --browser chromium
   ```
   Якщо `.env` немає, тести будуть `SKIPPED`: скажи про це прямо й познач поведінку як неперевірену.
3. **Пройди чекліст** нижче. Кожне зауваження перевір у коді або запуском, відкинь непідтверджене.
4. **Оформи результат** за шаблоном. Нічого не виправляй, якщо про це не просили.

## Чекліст за спаданням важливості

### Блокери: тест бреше

- **Гонка, що дає хибний pass.** `expect` на значення, яке вже істинне до завершення дії («лічильник
  лишився 6»). Потрібен сигнал завершення. Реальний випадок: `test_loading_demo_twice_...`
  давав XPASS, хоча баг був.
- **Xfail з іншої причини.** `known_bug`-тест падає через локатор чи таймаут, а не через дефект: звір
  повідомлення `--runxfail` із описом бага.
- **Перевірка, що не може впасти:** немає `expect` / `assert`, порівняння із самим собою, очікування
  обчислене тією ж логікою, що й у застосунку.
- **Широкий збіг:** `to_contain_text`, регулярний вираз або `.first`, які пропустять неправильний результат.
- **`assert` не дочекався дії:** читання localStorage чи файлу без попереднього `expect`.
- **Секрети** в коді, логах, тестових даних; закомічений `.env`.

### Важливо: тест зламається або заплутає

- Залежність від порядку тестів чи спільного стану; стан не засіяно через фікстури до навігації.
- Фіксовані паузи (`wait_for_timeout`, `sleep`), стандартний таймаут для сторонніх тайлів або клік по карті без `wait_until_idle`.
- Логіка в тесті, яку не ловить скрипт: у хелпері, що лише приховує обчислення очікуваного значення.
- `assert` / `expect` у `framework/`; локатори або «магічні» тексти в `tests/`.
- Текст інтерфейсу вписаний у тест замість ключа в `ui_texts.json`; дублікат у JSON замість посилання `{@...}`.
- CSS замість `get_by_role` / `get_by_label` там, де ролі є; локатор не обмежений коренем компонента.
- Назва не описує поведінку; кілька поведінок в одному тесті; `parametrize` без читабельних `ids`.
- Очікування порядку або даних, що не відповідають файлу в `test_data/`.
- Втрата покриття: видалена перевірка не має заміни, і це не узгоджено.

### Узгодженість артефактів

- `known_bug` є в `BUGS`; виправлений дефект прибрано з маркера, реєстру й статусів.
- Посилання на тести в `docs/checklist.md`, `docs/test-cases.md`, `docs/bug-reports.md` існують.
- Лічильники в `README.md` (баги, smoke, останній прогін) актуальні.
- Нові файли в `test_data/` описані в `docs/test-data.md`.
- Описи, дефекти, docstring'и й коментарі українською.
- Мертвий код: хелпери, фікстури чи моделі, якими більше ніхто не користується.

## Шаблон результату

```
## Вердикт: готово / є зауваження / не готово

### Блокери
- `tests/ui/test_x.py:42` — що не так. Сценарій: за яких умов тест дасть неправильний результат.
  Виправлення: що зробити.

### Важливо
- ...

### Перевірено
lint.sh: ... · pytest: N passed, M xfailed · --runxfail: причини збігаються
```

Порожні секції пропускай. Кожне зауваження містить файл із рядком і конкретний сценарій. Побажання
без наслідків не включай.
